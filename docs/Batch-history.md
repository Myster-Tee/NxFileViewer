# Batch history and resume

The batch page offers the last five sessions, with date, source path, result count and state. **Show** displays the recorded results without starting a task. **Resume** rereads the source and processes pending, changed or failed entries. New files are included. Completed entries are skipped only when their size and last-write timestamp still match, and the missing-delta-fragment verification policy is unchanged.

Archive entries use the parent ZIP/7z file's size and timestamp. Firmware folders use the sorted file list, names, sizes and timestamps. Fingerprints are captured before and after processing; a source changed during processing cannot be skipped on resume. This is a metadata change check, not an additional cryptographic hash check. A cancelled integrity check resumes verification; a cancelled metadata scan resumes scanning.

History is written atomically to `History/batch-integrity.json` beside the executable, at most once a second during result callbacks and again when a run finishes or is cancelled. Unexpected termination may lose the last second of completed results; those files are checked again. The most recent five distinct runs are retained, and resuming updates the same run. Historical results include table metadata and firmware details, not decrypted content or key values. Full file overview objects are not persisted. The historical game overview displays the saved title, ID, publisher, versions, structure, compression and integrity result without reopening files or archives. Loading a session selects its first visible result; active scans follow the current game package automatically.

The program directory must be writable. There is no AppData fallback. History errors are logged and do not abort the check. Missing source directories cannot be resumed, but their saved results can still be displayed. History states: Running, Interrupted, Completed (completion of processing does not mean all files passed).
History can be disabled under Settings → Program. This hides history controls and stops checkpoint reads/writes; existing files remain available after enabling it again. The preference is saved in the application settings JSON file and defaults to enabled.
